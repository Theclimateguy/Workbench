# О чём это руководство

Workstation (системный блок, Ubuntu Server 24.04, два GPU) уезжает в поле, где нет сети и нет инженера. Вместе с ней едет **Spark** — компактный компьютер на NVIDIA GB10 с локальной языковой моделью и агентом техподдержки. «Spark» в этом руководстве — любое из устройств: NVIDIA DGX Spark, ASUS Ascent GX10 или другой компьютер на GB10 с DGX OS; они одинаковы по портам, памяти и программам, отличия отмечены отдельно. Агент подключается к workstation по кабелю, читает её логи и конфигурацию, объясняет, что сломалось, и чинит или дорабатывает систему — **каждое изменение только после вашего подтверждения**.

Кроме workstation агент умеет работать и с другой техникой на объекте: контроллеры и платы по **USB-serial**, шина **CAN** через USB-CAN-адаптер, промышленные устройства по **Modbus** (TCP или RS-485), приборы с **web-интерфейсом**. Как их подключить — раздел «Другие устройства». Воздействие на такое оборудование (команда в консоль платы, кадр в CAN, запись регистра) подтверждается **каждый раз отдельно**, кнопки «разрешить всегда» для него нет.

Руководство рассчитано на оператора без глубоких знаний Linux. Всё, что нужно вводить руками, выделено так: `support-ctl status`.

Чего агент **не** делает: не выходит в интернет (его нет), не скачивает пакеты из сети, не меняет ничего без вашего «Разрешить».

Комплект рассчитан на работу **в любой сети и без сети**: всё, что нужно агенту, живёт внутри Spark, а workstation он находит по имени и MAC-адресу, а не по IP, который в поле будет другим.

# Перед выездом: контрольный список

Проверяется в офисе, где есть сеть и время. В поле исправить это будет сложно.

1. **Spark загружается и стек «зелёный».** Включите Spark, войдите, в терминале: `support-ctl status`. Должно быть: `llm@fast: active`, `serving: fast`, в «Devices» есть `ws`, в «Workbench» — `image workbench:local` (песочница собрана).
2. **Workstation зарегистрирована.** На Spark: `support-ctl target test ws` → строки `ok: <имя workstation>` и `sudo: ok`. Если нет — раздел «Регистрация workstation».
3. **Прямой кабель проверен.** Соедините Spark и workstation кабелем **без** роутера, подождите 30 с, `support-ctl net peers` должен показать workstation. Повторите `support-ctl target test ws`.
4. **Документация загружена.** `support-ctl docs status` показывает ваши файлы (не только README). Чем полнее описана workstation, тем точнее агент.
5. **Пароли записаны** (раздел «Пароли»), лист в комплекте.
6. **Точка доступа проверена и включён автозапуск**, если в поле будете работать с ноутбука: `support-ctl net hotspot on`, подключиться, открыть `http://10.42.0.1:8080`, затем `support-ctl net hotspot off` и `support-ctl net hotspot auto on`.
7. **Нужные пакеты заранее на флешке**, если известно, что в поле понадобится что-то ставить (`.deb` для amd64 с зависимостями). Агент не скачает их из интернета.
8. **Другие устройства зарегистрированы и проверены**, если едете к контроллеру/шине/ПЛК: `support-ctl device list`, затем `support-ctl device test ИМЯ` для каждого (раздел «Другие устройства»). Документация на них (карта регистров, список CAN-идентификаторов, распиновка) — в папку документации (п. 4): без неё агент «щупает вслепую» и скажет об этом.

# Включение Spark

1. Подключите адаптер питания в **USB-C с пометкой питания на задней панели** (у ASUS GX10 и DGX Spark это крайний левый порт; остальные три USB-C — для периферии). Адаптер — в розетку.
2. Подключите монитор к **HDMI**, клавиатуру и мышь — к любому USB-C (через переходник, если они USB-A). Если работаете с ноутбука — монитор не нужен, см. раздел «Способ 2».
3. Нажмите **кнопку питания** (ASUS GX10 — на передней панели, DGX Spark — сверху у переднего края). Загрузка ~1 минута, появится экран входа.
4. Войдите под пользователем-оператором (на комплектных устройствах — `admin`, см. лист паролей). Откроется обычный рабочий стол (GNOME).
5. **Подождите ещё 5–6 минут**: языковая модель загружается в память автоматически. Готовность проверяется в терминале (`Ctrl+Alt+T`):

```
support-ctl status
```

Готово, когда строка `llm@fast: active` и `serving: fast`. Пока модель грузится, интерфейс агента покажет «LLM offline» — это нормально.

Выключение: меню питания в правом верхнем углу → «Выключить», либо в терминале `sudo poweroff`. Не выдёргивайте питание во время работы агента.

# Подключение к workstation

## Три сетевых ситуации

| Ситуация | Как соединить | Адрес Spark | Как Spark находит workstation |
|:--------|:----------|:----------|:------------|
| **Нет сети вообще** (основной полевой случай) | прямой кабель RJ45 Spark ↔ workstation | `10.77.0.1` на кабеле, `10.42.0.1` на своей Wi-Fi-точке | сам выдаёт ей адрес по DHCP и видит её по имени/MAC |
| **Чужая локальная сеть** (на объекте есть роутер) | обе машины в роутер **или** всё равно прямым кабелем | выдаст роутер; узнать: `support-ctl status` | по имени (`имя.local`) или по MAC в этой сети |
| **Офис** | как привыкли | из офисной сети | по имени |

Прямой кабель работает во всех трёх случаях и не зависит от чужой сети — **в поле используйте его**. Чужую сеть подключайте только если нужен её ресурс (например, принтер или общий диск).

Адреса в поле меняются, но вам не нужно их знать: интерфейс агента открывается по `localhost` на самом Spark или по `10.42.0.1` через его точку доступа, а workstation агент находит сам. Если всё же нужен текущий адрес Spark — `support-ctl status` печатает все ссылки на интерфейс.

## Прямой кабель

Один кабель RJ45: порт **10G LAN** на задней панели Spark (единственный RJ45, не путать с двумя широкими QSFP-портами) ↔ сетевой порт workstation, который настроен на DHCP (обычно — тот же, которым она подключалась к сети в офисе).

Что происходит автоматически:

- Spark ~20 с пытается найти в кабеле «обычную сеть»; не находит — переключается в режим **direct**: сам становится DHCP-сервером с адресом `10.77.0.1`.
- Workstation получает адрес `10.77.0.x`.

Проверка (терминал Spark):

```
support-ctl net status
support-ctl net peers
support-ctl target test ws
```

Ожидаемо: `profile: direct`, в peers — адрес и имя workstation, в test — `ok` и `sudo: ok`.

`target test` сам ищет workstation в таком порядке: по имени (`имя.local`), по MAC среди выданных DHCP-адресов, по MAC в таблице соседей (включая IPv6 link-local, если DHCP на workstation выключен), по последнему удачному адресу. Строка `resolved: …` показывает, что нашлось. Если workstation переименовали или заменили сетевую карту — зарегистрируйте заново:

```
support-ctl target add ws ВАШ_ПОЛЬЗОВАТЕЛЬ@10.77.0.XX
```

(спросит пароль вашего пользователя на workstation; адрес подсмотреть в `net peers`).

Если workstation не появляется в `net peers` через минуту — раздел «Если что-то не работает → Workstation не видна».

Порядок включения не важен: можно включить обе машины и потом соединить кабелем.

# Как открыть интерфейс агента

## Способ 1 — монитор и клавиатура на Spark (основной)

Откройте браузер (Firefox на панели слева) и перейдите на

```
http://localhost:8080
```

Логин `support`, пароль из таблицы.

## Способ 2 — ноутбук или телефон по Wi-Fi

В терминале Spark (или заранее, перед выездом):

```
support-ctl net hotspot on
```

Команда напечатает имя сети `Workbench-Support` и пароль. Подключите ноутбук/телефон к этой сети и откройте `http://10.42.0.1:8080` (или `http://<имя-устройства>.local:8080`). Выключить: `support-ctl net hotspot off`.

**Голос и «как приложение» — только по HTTPS.** Браузер даёт доступ к микрофону и ставит страницу как приложение только с защищённого адреса. Один раз на ноутбуке/телефоне:

1. Скачайте сертификат Spark: `http://10.42.0.1:8080/ca.crt`.
2. Установите его как доверенный корневой: macOS — двойной клик, Связка ключей → «Всегда доверять»; Windows — «Установить сертификат» → «Доверенные корневые центры»; iPhone — Настройки → Профиль загружен → установить, затем Основные → Об устройстве → Доверие сертификатам → включить; Android — Настройки → Безопасность → Установить сертификат ЦС.
3. Открывайте `https://10.42.0.1:8443` (или `https://имя-gx10.local:8443`). Замок в адресной строке — зелёный.

Дальше в интерфейсе появится кнопка **«Установить»** (ярлык на рабочем столе ноутбука, окно без адресной строки) и кнопка **микрофона**.

**Ноутбук по кабелю без сертификата.** Если ноутбук соединён с Spark кабелем (или находится в его хотспоте) и на нём есть терминал, можно обойтись без установки `ca.crt`: пробросить интерфейс на свой `localhost` по SSH — браузер считает `localhost` защищённым адресом, микрофон и установка приложения работают.

```
ssh -N -L 18080:127.0.0.1:8080 admin@10.77.0.1
```

Оставьте команду работать и откройте в браузере `http://localhost:18080` (пароль не спросит — для Spark это локальный запрос). В хотспоте вместо `10.77.0.1` — `10.42.0.1`.

Чтобы в поле не подключать монитор ради одной команды, **перед выездом** включите автозапуск: `support-ctl net hotspot auto on`. Тогда при загрузке, если рядом нет известной Wi-Fi-сети (офисной), Spark сам поднимет точку доступа; в офисе он по-прежнему подключится к офисному Wi-Fi. Отключить автозапуск: `support-ctl net hotspot auto off`.

## Способ 3 — текстовый режим из консоли workstation

Если под рукой только клавиатура workstation (без графики), с неё по тому же кабелю:

```
ssh admin@10.77.0.1 -t support-ctl agent
```

Откроется текстовый интерфейс агента. Подтверждения здесь — клавишами, подсказки на экране. Выход: `Ctrl+C` дважды или `/exit`.

# Работа с агентом

## Экран

- **Вверху:** переключатель **«Сессия | Аудит»** (аудит — таблица всех действий агента на устройствах с кнопками экспорта CSV/JSONL), **«Экспорт»** — скачать текущую сессию файлом Markdown; справа — тумблер модели **fast | deep** (переключение 6–12 минут, текущий ответ агента прервётся — интерфейс переспросит), точки состояния LLM и устройств (`ws`, `plc:modbus`, …), кнопка **«Установить»** (как приложение на ноутбук), переключатель светлой/тёмной темы. Пока агент работает — «думает…» и **Стоп**.
- **Слева:** список сессий с датой и кнопка **«+ Новая»**; внизу — какие устройства зарегистрированы (имя, тип, адрес или порт) и сколько документации загружено.
- **Посередине:** диалог. Ваши сообщения — синие справа. Ответы агента оформлены: заголовки, таблицы, списки, блоки команд (их можно выделить и скопировать). Вызовы инструментов — короткие строки с зелёной галочкой (успех) или красным крестом (ошибка), названием, устройством и временем; название инструмента окрашено по классу действия: чёрное — чтение, оранжевое — изменение настроек, красное — воздействие на оборудование. Щёлкните строку, чтобы увидеть команду и её вывод. «ход мыслей ›» — внутренние размышления модели, можно не читать.
- **Внизу:** кнопка микрофона (голосовой ввод, см. ниже), поле ввода (`Enter` — отправить, `Shift+Enter` — новая строка), **Отправить**.
- **Прокрутка:** лента сама следует за новыми сообщениями агента. Прокрутили вверх почитать — слежение останавливается, справа внизу появляется кнопка **«↓ вниз»**; нажмите её (или отправьте сообщение) — слежение возобновится.

Начинайте каждую новую задачу с кнопки **«+ Новая»** — так агент не путает контексты.

## Голосовой ввод

Кнопка с микрофоном слева от поля ввода (видна по HTTPS, через `localhost`-туннель или на самом Spark). Нажмите — говорите — нажмите ещё раз; или пробел, когда курсор не в поле ввода. Распознавание идёт **в браузере ноутбука, без интернета и без нагрузки на Spark** (модель Whisper, ~0.3 ГБ, скачивается с Spark при первом нажатии и кэшируется). Текст появляется в поле ввода — проверьте и отправьте Enter. Агент ничего не делает по голосу напрямую, подтверждения — только кнопками.

## Как ставить задачу

Пишите по-русски, как коллеге-инженеру. Хорошая задача содержит: что наблюдаете, когда началось, что уже пробовали.

Примеры:

- «Сервис `inference` не стартует после перезагрузки. Найди причину и предложи исправление.»
- «Проверь состояние обеих видеокарт и драйвера, есть ли ошибки в логах за сегодня.»
- «Диск заполнен. Найди, что занимает место, и освободи минимум 20 ГБ, не трогая данные в `/data`.»
- «По инструкции из документации настрой ротацию логов для сервиса `collector`.»
- «В скрипте `/opt/app/run.sh` после обновления не задаётся переменная `CUDA_VISIBLE_DEVICES`. Исправь, чтобы использовались обе карты.»
- «Сделай полный отчёт о состоянии workstation: железо, диски, сеть, сервисы, ошибки.»

Агент сначала **читает** (это разрешено без вопросов), потом объясняет, что нашёл, и предлагает изменение.

## Карточка подтверждения

Агент делит свои действия на три класса. **Чтение** (логи, файлы, состояние служб, прослушивание шины, чтение регистров) он делает без вопросов. Остальное — только через карточку в ленте:

| Класс | Карточка | Что это | Кнопки |
|:------|:--------|:--------|:-------|
| **Изменение** | жёлтая полоса слева, подпись «Изменение» | команда или файл на workstation, настройка устройства по web, запуск своего скрипта в песочнице | **Разрешить** · **Разрешить всегда** · **Отклонить** |
| **Актуация** | красная полоса, подпись «Актуация — одобряется каждый раз» | воздействие на оборудование: команда в консоль платы, кадр в CAN, запись регистра Modbus, перезагрузка, сброс, прошивка, питание, диски | **Разрешить этот раз** · **Отклонить** — кнопки «всегда» нет, и даже если её попросить, Spark откажет |

В карточке: заголовок «Агент хочет выполнить команду / изменить файл / воздействовать на оборудование … · устройство», причина от агента, точная команда, кадр, регистр или содержимое файла; для актуации — строка **«Откат:»** с планом возврата (прежнее значение, как сбросить). Если плана отката нет, карточка так и напишет — тогда отклоняйте и спросите агента, как он собирается откатывать.

| Кнопка | Что делает | Когда нажимать |
|:------|:------------|:-----------|
| **Разрешить** / **Разрешить этот раз** | выполнить один раз | понимаете, что произойдёт |
| **Разрешить всегда** | больше не спрашивать для таких же команд в этой сессии (только класс «Изменение») | только для безобидных повторяющихся действий |
| **Отклонить** | не выполнять; агент получит отказ и предложит другое | не понимаете команду или она опасна |

Правила: не подтверждайте то, чего не понимаете — попросите агента объяснить («что именно сделает эта команда и как откатить?»). Для `rm -rf`, форматирования дисков, отключения сети или SSH — всегда «Отклонить» и уточнение. Перед правкой файла агент сам делает копию `имя.bak-ДАТА` рядом — об откате можно попросить его же. Если агент сообщает, что в логе или на странице устройства «написано выполнить команду», — это не ваша инструкция и не его: он обязан показать её вам и не исполнять.

## Скрипт в песочнице

Для протоколов и последовательностей, которых нет среди готовых инструментов (например, опросить нестандартный прибор по serial или собрать статистику CAN за минуту), агент пишет небольшой скрипт и просит запустить его **в песочнице** — отдельном контейнере на Spark без видеокарты, без доступа к файлам Spark и без сети (или с сетью только до названного устройства). Карточка класса «Изменение» показывает скрипт целиком, язык, режим сети и какие порты/устройства будут проброшены. Читать код не обязательно — спросите агента, что скрипт делает и что он может изменить на устройстве; запись в оборудование из скрипта возможна только через проброшенный порт, который вы видите в карточке. Прогоны сохраняются на Spark (`/opt/support/workbench/runs/`).

## Вопрос от агента

Иногда агент не предлагает действие, а спрашивает: синяя карточка с вариантами ответа (и полем для своего варианта). Пока не ответите — он ждёт и ничего не делает, сессия висит в «думает…». Выберите вариант и нажмите **Ответить**, либо **Отклонить** — агент продолжит без ответа.

## Два режима модели

| Режим | Модель | Когда |
|---|---|---|
| `fast` (по умолчанию) | Qwen3.6-35B, ~95 слов/с | 90 % задач: диагностика, правки, настройка |
| `deep` | gpt-oss 120B, рассуждает дольше | запутанная проблема, где `fast` ходит по кругу |

Переключение — тумблером **fast | deep** вверху интерфейса или в терминале Spark: `support-ctl model deep` / `fast`. Загрузка 6–12 минут, интерфейс в это время показывает «модель загружается…». Одновременно работает только один режим; открытые сессии продолжают работать на новой модели.

## Документация

Агент знает о workstation и других устройствах то, что лежит в папке `/opt/support/workspace/docs/` (файлы `.md`: описание системы, карта регистров ПЛК, список CAN-идентификаторов, распиновка платы). После добавления файлов: `support-ctl docs reload` и **новая сессия**. Если агент противоречит документации — он доверяет тому, что видит на устройстве, и сообщит о расхождении.

## Журнал

Все действия агента на workstation — в журнале слева и в файле `/var/log/support/audit.jsonl` на Spark: время, команда, причина, результат. Попытки выполнить изменяющую команду через инструмент только для чтения отмечены как «rejected» — это нормальная работа защиты.

# Другие устройства

Помимо workstation (Linux по SSH) Spark подключается к технике напрямую. Устройство регистрируется один раз командой `support-ctl device add`, после этого агент видит его в списке и обращается к нему по имени. Подключение — через USB-хаб к любому USB-C Spark; порты видны командой `support-ctl scan` (её же может вызвать агент — попросите «посмотри, что подключено»).

| Тип | Как подключить | Регистрация | Что агент может |
|:----|:---------------|:------------|:----------------|
| **Консоль платы / контроллера** (UART через USB-serial) | адаптер USB-serial → UART платы (GND, TX↔RX); узнать порт: `support-ctl scan serial` | `support-ctl device add esp serial PORT=/dev/ttyUSB0 BAUD=115200` | слушать вывод (без вопросов); отправить строку, сброс платы импульсом DTR (актуация) |
| **Шина CAN** (USB-CAN-адаптер, CANable/gs_usb) | адаптер в USB, CAN-H/CAN-L/GND к шине; поднять интерфейс: `sudo /opt/support/bin/support-priv can-restart can0 500000` | `support-ctl device add bus can IFACE=can0 BITRATE=500000` | дамп кадров со счётчиками по идентификаторам (без вопросов); отправить кадр, перезапустить интерфейс при bus-off (актуация) |
| **Modbus TCP** (ПЛК, частотник, счётчик по Ethernet) | в ту же сеть, что Spark (прямой кабель через коммутатор или чужая сеть) | `support-ctl device add plc modbus HOST=10.77.0.20 PORT=502 UNIT=1` | читать регистры и катушки, паспорт устройства (без вопросов); записать регистр/катушку с обратным чтением (актуация) |
| **Modbus RTU** (RS-485) | адаптер USB-RS485: A/B/GND | `support-ctl device add drive modbus PORT=/dev/ttyUSB1 BAUD=9600 UNIT=2` | то же |
| **Прибор с web-интерфейсом / REST** | по сети | `support-ctl device add cam http URL=http://10.77.0.30 AUTH=admin:пароль` (самоподписанный HTTPS: `VERIFY=0`) | открывать страницы и API (GET — без вопросов); менять настройки через POST/PUT (изменение) |

Проверка после регистрации: `support-ctl device test ИМЯ` — печатает, как Spark видит устройство (первая строка ответа). Список: `support-ctl device list`; удалить: `support-ctl device rm ИМЯ`.

Что важно знать:

- Консоль платы агент **только слушает**, пока вы не разрешите отправку конкретной строки — набрать в консоль он может что угодно, поэтому каждая строка идёт карточкой «Актуация».
- Для CAN и Modbus агент сначала смотрит документацию в папке `docs/`; без карты регистров или списка идентификаторов он честно скажет, что пробует наугад — дайте ему документацию или подскажите адреса.
- Прошивка (esptool, OpenOCD и т. п.) — только из песочницы с явным пробросом USB и только с образом, происхождение и модель которого вы подтвердили; агент обязан сохранить текущую прошивку, если устройство это позволяет.

Примеры задач: «Послушай консоль esp 10 секунд и скажи, в чём ошибка загрузки», «На шине bus посмотри, какие идентификаторы живые, и найди узел, который молчит», «Прочитай у plc регистры 0–20 и сверь с картой регистров в документации», «Установи у drive уставку частоты 25 Гц» (это актуация — будет карточка с планом отката).

# Типовые сценарии

## Сервис не стартует

Задача агенту: «Сервис X не запускается, разберись». Агент прочитает `systemctl status`, журнал, конфигурацию. Типичный исход — правка конфигурации (карточка `write_file`, в ней виден diff) и перезапуск (`run_change systemctl restart X`). Подтвердите обе, затем попросите: «проверь, что сервис работает и в логах нет ошибок».

## Нет сети на workstation

Пока workstation на прямом кабеле с Spark, её «боевая» сеть всё равно может быть сломана. Агент видит `netplan`, `ip`, `resolvectl`. Осторожно с подтверждениями `netplan apply`: если агент меняет интерфейс, через который он сам подключён, связь прервётся. Попросите его явно: «не трогай интерфейс, через который ты подключён».

## Установить или обновить пакет без интернета

`apt install` в поле не сработает — скажите агенту об этом сразу: «интернета нет, пакеты только с флешки». Вставьте флешку в workstation (или в Spark — тогда агент перенесёт файл сам через `write_file` только для текстовых файлов; бинарные `.deb` лучше класть на workstation). Задача: «установи `/media/usb/pkg.deb` вместе с зависимостями из той же папки».

## Проблемы с GPU

«Проверь обе видеокарты: `nvidia-smi`, версия драйвера против версии модуля ядра, ошибки Xid в `dmesg`». Частые причины после обновлений — несовпадение версий драйвера и ядра; агент предложит либо переустановку из кэша `apt`, либо откат ядра через GRUB. Перезагрузку он запросит отдельной карточкой (`reboot_and_wait`) и дождётся возврата.

## Доработка настроек или кода

«Добавь в `/etc/app/config.yaml` параметр … согласно документации, раздел …». Агент покажет diff в карточке. Для кода: «исправь скрипт так, чтобы …; покажи diff; запусти проверку синтаксиса». Тесты запускает он же — через `run_change`, если тест что-то пишет на диск.

# Если что-то не работает

| Симптом | Что проверить | Что сделать |
|:----------|:-----------|:-------------|
| В интерфейсе «LLM offline» дольше 7 минут после включения | `support-ctl status`; `journalctl -u llm@fast -n 50` | `sudo systemctl restart llm@fast`, подождать 6 минут. Если `deep` был включён — `support-ctl model fast` |
| Страница `:8080` не открывается | `systemctl status support-ui support-opencode` | `support-ctl web` (перезапустит оба сервиса; пароль не меняет) |

| Workstation не видна (`net peers` пусто) | индикаторы на портах горят? `support-ctl net status` → `profile: direct`? | переткнуть кабель; если профиль `lan` — `support-ctl net direct`; на workstation убедиться, что порт настроен на DHCP (см. Приложение Б) |

| Агент «думает» бесконечно | нажать **Стоп** | переформулировать задачу короче; новая сессия |

| CAN: `cannot open can0` | `support-ctl scan can` — интерфейс есть, но DOWN? | `sudo /opt/support/bin/support-priv can-restart can0 500000` (битрейт шины); или попросить агента «восстанови bus» |
| Modbus: `cannot connect` / таймаут | адрес и порт верны, `UNIT` совпадает с адресом устройства? RS-485: A/B не перепутаны, скорость/чётность? | `support-ctl device add …` с правильными параметрами |

# Приложение А. Регистрация workstation

Делается один раз, в офисе, по сети или по прямому кабелю. Нужен ваш пользователь на workstation с правом `sudo`.

```
support-ctl target add ws ПОЛЬЗОВАТЕЛЬ@АДРЕС_WORKSTATION
```

Что происходит: на workstation создаётся пользователь `support-agent` (вход только по ключу Spark, пароль заблокирован, `sudo` без пароля), ключ Spark копируется ему, ставится служба `avahi-daemon`, чтобы workstation отзывалась по имени `имя.local` в любой сети (если на workstation в этот момент есть интернет; без неё Spark найдёт её по MAC). Spark запоминает имя и MAC-адрес workstation, а не её IP. Проверка: `support-ctl target test ws`.

Удалить доступ агента с workstation (на ней, под root):

```
userdel -r support-agent; rm -f /etc/sudoers.d/90-support-agent /etc/ssh/sshd_config.d/90-support-agent.conf
```

# Приложение А2. Регистрация других устройств

Команда одна для всех типов: `support-ctl device add ИМЯ ТИП КЛЮЧ=ЗНАЧЕНИЕ …`, после неё автоматически выполняется `device test`. Имя — латиницей, без пробелов; им вы называете устройство агенту.

| ТИП | Обязательные ключи | Необязательные |
|:----|:------------------|:---------------|
| `serial` | `PORT=/dev/ttyUSB0` (или `/dev/serial/by-id/…` — не меняется при переподключении) | `BAUD=115200`, `EOL=\n` (конец строки при отправке: `\r\n` для некоторых консолей) |
| `can` | `IFACE=can0` | `BITRATE=500000` |
| `modbus` | TCP: `HOST=…` ; RTU: `PORT=/dev/ttyUSB1` | `PORT=502`, `UNIT=1` (адрес устройства), `BAUD=9600` (RTU) |
| `http` | `URL=http://адрес[:порт]` | `AUTH=логин:пароль`, `TOKEN=…` (Bearer), `VERIFY=0` (самоподписанный сертификат) |

Файл устройства — `/opt/support/targets/ИМЯ.env`, его можно править руками. Порт serial лучше указывать по `/dev/serial/by-id/` (посмотреть: `support-ctl scan serial`), тогда номер `ttyUSB` не важен.

# Приложение Б. Сетевой порт workstation для прямого кабеля

Порт workstation, в который втыкается кабель от Spark, должен получать адрес по DHCP. Пример `/etc/netplan/50-field.yaml` (имя интерфейса узнать: `ip -br link`):

```yaml
network:
  version: 2
  ethernets:
    enp5s0:
      dhcp4: true
      optional: true
```

Применить: `sudo netplan apply`. `optional: true` — чтобы workstation не ждала этот порт при загрузке, когда кабель не подключён.

Если DHCP на workstation включить нельзя, задайте статический адрес `10.77.0.2/24` без шлюза. Spark тоже сможет найти её по IPv6 link-local (`support-ctl net peers` покажет `fe80::…`), но регистрировать цель тогда нужно по этому адресу.

# Приложение Г. Новый Spark с нуля

Репозиторий проекта: `https://github.com/Theclimateguy/Workbench`. Полная инструкция — файл `docs/DEPLOY.md` в нём. Кратко: штатная установка DGX OS (пользователь-оператор с `sudo` без пароля, см. DEPLOY.md), затем на устройстве с интернетом:

```
git clone https://github.com/Theclimateguy/Workbench.git ~/Workbench
cd ~/Workbench && ./install/bootstrap.sh --with-deep
```

Скачивает ~95 ГБ, занимает около полутора часов, в конце печатает адреса и пароль. Повторный запуск продолжает с места обрыва.
