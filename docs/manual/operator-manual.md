# О чём это руководство

Workstation (системный блок, Ubuntu Server 24.04, два GPU) уезжает в поле, где нет сети и нет инженера. Вместе с ней едет **ASUS Ascent GX10** — компактный компьютер с локальной языковой моделью и агентом техподдержки. Агент подключается к workstation по кабелю, читает её логи и конфигурацию, объясняет, что сломалось, и чинит или дорабатывает систему — **каждое изменение только после вашего подтверждения**.

Руководство рассчитано на оператора без глубоких знаний Linux. Всё, что нужно вводить руками, выделено так: `support-ctl status`.

Чего агент **не** делает: не выходит в интернет (его нет), не скачивает пакеты из сети, не меняет ничего без вашего «Разрешить».

Комплект рассчитан на работу **в любой сети и без сети**: всё, что нужно агенту, живёт внутри GX10, а workstation он находит по имени и MAC-адресу, а не по IP, который в поле будет другим.

# Перед выездом: контрольный список

Проверяется в офисе, где есть сеть и время. В поле исправить это будет сложно.

1. **GX10 загружается и стек «зелёный».** Включите GX10, войдите, в терминале: `support-ctl status`. Должно быть: `llm@fast: active`, `serving: fast`, в «Targets» есть `ws`.
2. **Workstation зарегистрирована.** На GX10: `support-ctl target test ws` → строки `ok: <имя workstation>` и `sudo: ok`. Если нет — раздел «Регистрация workstation».
3. **Прямой кабель проверен.** Соедините GX10 и workstation кабелем **без** роутера, подождите 30 с, `support-ctl net peers` должен показать workstation. Повторите `support-ctl target test ws`.
4. **Документация загружена.** `support-ctl docs status` показывает ваши файлы (не только README). Чем полнее описана workstation, тем точнее агент.
5. **Пароли записаны** (раздел «Пароли»), лист в комплекте.
6. **Точка доступа проверена и включён автозапуск**, если в поле будете работать с ноутбука: `support-ctl net hotspot on`, подключиться, открыть `http://10.42.0.1:8080`, затем `support-ctl net hotspot off` и `support-ctl net hotspot auto on`.
7. **Нужные пакеты заранее на флешке**, если известно, что в поле понадобится что-то ставить (`.deb` для amd64 с зависимостями). Агент не скачает их из интернета.

# Включение GX10

1. Подключите адаптер питания в **левый USB-C на задней панели** (это единственный порт с приёмом питания; остальные три USB-C — для периферии). Адаптер — в розетку.
2. Подключите монитор к **HDMI**, клавиатуру и мышь — к любому USB-C (через переходник, если они USB-A). Если работаете с ноутбука — монитор не нужен, см. раздел «Способ 2».
3. Нажмите **кнопку питания на передней панели**. Загрузка ~1 минута, появится экран входа.
4. Войдите как `admin`. Откроется обычный рабочий стол (GNOME).
5. **Подождите ещё 5–6 минут**: языковая модель загружается в память автоматически. Готовность проверяется в терминале (`Ctrl+Alt+T`):

```
support-ctl status
```

Готово, когда строка `llm@fast: active` и `serving: fast`. Пока модель грузится, интерфейс агента покажет «LLM offline» — это нормально.

Выключение: меню питания в правом верхнем углу → «Выключить», либо в терминале `sudo poweroff`. Не выдёргивайте питание во время работы агента.

# Подключение к workstation

## Три сетевых ситуации

| Ситуация | Как соединить | Адрес GX10 | Как GX10 находит workstation |
|:--------|:----------|:----------|:------------|
| **Нет сети вообще** (основной полевой случай) | прямой кабель RJ45 GX10 ↔ workstation | `10.77.0.1` на кабеле, `10.42.0.1` на своей Wi-Fi-точке | сам выдаёт ей адрес по DHCP и видит её по имени/MAC |
| **Чужая локальная сеть** (на объекте есть роутер) | обе машины в роутер **или** всё равно прямым кабелем | выдаст роутер; узнать: `support-ctl status` | по имени (`имя.local`) или по MAC в этой сети |
| **Офис** | как привыкли | из офисной сети | по имени |

Прямой кабель работает во всех трёх случаях и не зависит от чужой сети — **в поле используйте его**. Чужую сеть подключайте только если нужен её ресурс (например, принтер или общий диск).

Адреса в поле меняются, но вам не нужно их знать: интерфейс агента открывается по `localhost` на самом GX10 или по `10.42.0.1` через его точку доступа, а workstation агент находит сам. Если всё же нужен текущий адрес GX10 — `support-ctl status` печатает все ссылки на интерфейс.

## Прямой кабель

Один кабель RJ45: порт **10G LAN** на задней панели GX10 (единственный RJ45, не путать с двумя широкими QSFP-портами) ↔ сетевой порт workstation, который настроен на DHCP (обычно — тот же, которым она подключалась к сети в офисе).

Что происходит автоматически:

- GX10 ~20 с пытается найти в кабеле «обычную сеть»; не находит — переключается в режим **direct**: сам становится DHCP-сервером с адресом `10.77.0.1`.
- Workstation получает адрес `10.77.0.x`.

Проверка (терминал GX10):

```
support-ctl net status
support-ctl net peers
support-ctl target test ws
```

Ожидаемо: `profile: direct`, в peers — адрес и имя workstation, в test — `ok` и `sudo: ok`.

`target test` сам ищет workstation в таком порядке: по имени (`имя.local`), по MAC среди выданных DHCP-адресов, по MAC в таблице соседей (включая IPv6 link-local, если DHCP на workstation выключен), по последнему удачному адресу. Строка `resolved: …` показывает, что нашлось. Если workstation переименовали или заменили сетевую карту — зарегистрируйте заново:

```
support-ctl target add ws ВАШ_ПОЛЬЗОВАТЕЛЬ@10.77.0.XX
```

(спросит пароль вашего пользователя на workstation; адрес подсмотреть в `net peers`).

Если workstation не появляется в `net peers` через минуту — раздел «Если что-то не работает → Workstation не видна».

Порядок включения не важен: можно включить обе машины и потом соединить кабелем.

# Как открыть интерфейс агента

## Способ 1 — монитор и клавиатура на GX10 (основной)

Откройте браузер (Firefox на панели слева) и перейдите на

```
http://localhost:8080
```

Логин `support`, пароль из таблицы.

## Способ 2 — ноутбук или телефон по Wi-Fi

В терминале GX10 (или заранее, перед выездом):

```
support-ctl net hotspot on
```

Команда напечатает имя сети `GX10-Support` и пароль. Подключите ноутбук/телефон к этой сети и откройте `http://10.42.0.1:8080` (или `http://gx10-8409.local:8080`). Выключить: `support-ctl net hotspot off`.

Чтобы в поле не подключать монитор ради одной команды, **перед выездом** включите автозапуск: `support-ctl net hotspot auto on`. Тогда при загрузке, если рядом нет известной Wi-Fi-сети (офисной), GX10 сам поднимет точку доступа; в офисе он по-прежнему подключится к офисному Wi-Fi. Отключить автозапуск: `support-ctl net hotspot auto off`.

## Способ 3 — текстовый режим из консоли workstation

Если под рукой только клавиатура workstation (без графики), с неё по тому же кабелю:

```
ssh admin@10.77.0.1 -t support-ctl agent
```

Откроется текстовый интерфейс агента. Подтверждения здесь — клавишами, подсказки на экране. Выход: `Ctrl+C` дважды или `/exit`.

# Работа с агентом

## Экран

- **Слева:** состояние LLM (`online`/`offline`), зарегистрированные цели (`ws`), объём документации, список сессий, журнал действий.
- **Посередине:** диалог. Вызовы инструментов свёрнуты в серые строки — щёлкните, чтобы увидеть команду и её вывод. «рассуждение» — внутренние размышления модели, можно не читать.
- **Внизу:** поле ввода. `Enter` — отправить, `Shift+Enter` — новая строка. Кнопка **Стоп** прерывает агента.

Начинайте каждую новую задачу с кнопки **«+ новая»** — так агент не путает контексты.

## Как ставить задачу

Пишите по-русски, как коллеге-инженеру. Хорошая задача содержит: что наблюдаете, когда началось, что уже пробовали.

Примеры:

- «Сервис `inference` не стартует после перезагрузки. Найди причину и предложи исправление.»
- «Проверь состояние обеих видеокарт и драйвера, есть ли ошибки в логах за сегодня.»
- «Диск заполнен. Найди, что занимает место, и освободи минимум 20 ГБ, не трогая данные в `/data`.»
- «По инструкции из документации настрой ротацию логов для сервиса `collector`.»
- «В скрипте `/opt/app/run.sh` после обновления не задаётся переменная `CUDA_VISIBLE_DEVICES`. Исправь, чтобы использовались обе карты.»
- «Сделай полный отчёт о состоянии workstation: железо, диски, сеть, сервисы, ошибки.»

Агент сначала **читает** (это разрешено без вопросов), потом объясняет, что нашёл, и предлагает изменение.

## Карточка подтверждения

Перед каждым изменением появляется оранжевая карточка: цель (`ws`), точная команда или файл, причина от агента. Три кнопки:

| Кнопка | Что делает | Когда нажимать |
|:------|:------------|:-----------|
| **Разрешить** | выполнить один раз | понимаете, что произойдёт |
| **Разрешить и не спрашивать** | больше не спрашивать для таких же команд в этой сессии | только для безобидных повторяющихся действий |
| **Отклонить** | не выполнять; агент получит отказ и предложит другое | не понимаете команду или она опасна |

Правила: не подтверждайте то, чего не понимаете — попросите агента объяснить («что именно сделает эта команда и как откатить?»). Для `rm -rf`, форматирования дисков, отключения сети или SSH — всегда «Отклонить» и уточнение. Перед правкой файла агент сам делает копию `имя.bak-ДАТА` рядом — об откате можно попросить его же.

## Два режима модели

| Режим | Модель | Когда |
|---|---|---|
| `fast` (по умолчанию) | Qwen3.6-35B, ~95 слов/с | 90 % задач: диагностика, правки, настройка |
| `deep` | Nemotron 3 Super 120B, медленнее в ~4 раза | запутанная проблема, где `fast` ходит по кругу |

Переключение в терминале GX10: `support-ctl model deep` (загрузка ~7 минут, интерфейс в это время покажет `offline`), обратно — `support-ctl model fast`. Одновременно работает только один режим.

## Документация

Агент знает о workstation то, что лежит в папке `/opt/support/workspace/docs/` (файлы `.md`). После добавления файлов: `support-ctl docs reload` и **новая сессия**. Если агент противоречит документации — он доверяет тому, что видит на машине, и сообщит о расхождении.

## Журнал

Все действия агента на workstation — в журнале слева и в файле `/var/log/support/audit.jsonl` на GX10: время, команда, причина, результат. Попытки выполнить изменяющую команду через инструмент только для чтения отмечены как «rejected» — это нормальная работа защиты.

# Типовые сценарии

## Сервис не стартует

Задача агенту: «Сервис X не запускается, разберись». Агент прочитает `systemctl status`, журнал, конфигурацию. Типичный исход — правка конфигурации (карточка `write_file`, в ней виден diff) и перезапуск (`run_change systemctl restart X`). Подтвердите обе, затем попросите: «проверь, что сервис работает и в логах нет ошибок».

## Нет сети на workstation

Пока workstation на прямом кабеле с GX10, её «боевая» сеть всё равно может быть сломана. Агент видит `netplan`, `ip`, `resolvectl`. Осторожно с подтверждениями `netplan apply`: если агент меняет интерфейс, через который он сам подключён, связь прервётся. Попросите его явно: «не трогай интерфейс, через который ты подключён».

## Установить или обновить пакет без интернета

`apt install` в поле не сработает — скажите агенту об этом сразу: «интернета нет, пакеты только с флешки». Вставьте флешку в workstation (или в GX10 — тогда агент перенесёт файл сам через `write_file` только для текстовых файлов; бинарные `.deb` лучше класть на workstation). Задача: «установи `/media/usb/pkg.deb` вместе с зависимостями из той же папки».

## Проблемы с GPU

«Проверь обе видеокарты: `nvidia-smi`, версия драйвера против версии модуля ядра, ошибки Xid в `dmesg`». Частые причины после обновлений — несовпадение версий драйвера и ядра; агент предложит либо переустановку из кэша `apt`, либо откат ядра через GRUB. Перезагрузку он запросит отдельной карточкой (`reboot_and_wait`) и дождётся возврата.

## Доработка настроек или кода

«Добавь в `/etc/app/config.yaml` параметр … согласно документации, раздел …». Агент покажет diff в карточке. Для кода: «исправь скрипт так, чтобы …; покажи diff; запусти проверку синтаксиса». Тесты запускает он же — через `run_change`, если тест что-то пишет на диск.

# Если что-то не работает

| Симптом | Что проверить | Что сделать |
|:----------|:-----------|:-------------|
| В интерфейсе «LLM offline» дольше 7 минут после включения | `support-ctl status`; `journalctl -u llm@fast -n 50` | `sudo systemctl restart llm@fast`, подождать 6 минут. Если `deep` был включён — `support-ctl model fast` |
| Страница `:8080` не открывается | `systemctl status support-ui support-opencode` | `support-ctl web` (перезапустит оба сервиса; пароль не меняет) |
| Забыт пароль web | — | `support-ctl web НОВЫЙ_ПАРОЛЬ` |
| Workstation не видна (`net peers` пусто) | индикаторы на портах горят? `support-ctl net status` → `profile: direct`? | переткнуть кабель; если профиль `lan` — `support-ctl net direct`; на workstation убедиться, что порт настроен на DHCP (см. Приложение Б) |
| Workstation видна в `net peers`, но `target test ws` не находит её | MAC в peers совпадает с `MAC=` в `/opt/support/targets/ws.env`? | другая сетевая карта/машина — `support-ctl target add ws ПОЛЬЗОВАТЕЛЬ@АДРЕС` |
| `target test` — «REMOTE HOST IDENTIFICATION HAS CHANGED» | workstation переустановили | на GX10: `ssh-keygen -R ws`, затем `target test ws` |
| `sudo: MISSING` в `target test` | на workstation удалили `/etc/sudoers.d/90-support-agent` | повторить регистрацию (`target add`) |
| Агент «думает» бесконечно | нажать **Стоп** | переформулировать задачу короче; новая сессия |
| Агент отвечает не по делу / путает машину | открыта старая сессия? | «+ новая», сначала «собери факты о ws» |
| Точка доступа не появляется | `nmcli con show --active` | `support-ctl net hotspot off`, затем `on` |
| GX10 не загружается | — | восстановление с установочной флешки (отдельная инструкция, стирает GX10; документация и настройки хранятся в репозитории) |

# Приложение А. Регистрация workstation

Делается один раз, в офисе, по сети или по прямому кабелю. Нужен ваш пользователь на workstation с правом `sudo`.

```
support-ctl target add ws ПОЛЬЗОВАТЕЛЬ@АДРЕС_WORKSTATION
```

Что происходит: на workstation создаётся пользователь `support-agent` (вход только по ключу GX10, пароль заблокирован, `sudo` без пароля), ключ GX10 копируется ему, ставится служба `avahi-daemon`, чтобы workstation отзывалась по имени `имя.local` в любой сети (если на workstation в этот момент есть интернет; без неё GX10 найдёт её по MAC). GX10 запоминает имя и MAC-адрес workstation, а не её IP. Проверка: `support-ctl target test ws`.

Удалить доступ агента с workstation (на ней, под root):

```
userdel -r support-agent; rm -f /etc/sudoers.d/90-support-agent /etc/ssh/sshd_config.d/90-support-agent.conf
```

# Приложение Б. Сетевой порт workstation для прямого кабеля

Порт workstation, в который втыкается кабель от GX10, должен получать адрес по DHCP. Пример `/etc/netplan/50-field.yaml` (имя интерфейса узнать: `ip -br link`):

```yaml
network:
  version: 2
  ethernets:
    enp5s0:
      dhcp4: true
      optional: true
```

Применить: `sudo netplan apply`. `optional: true` — чтобы workstation не ждала этот порт при загрузке, когда кабель не подключён.

Если DHCP на workstation включить нельзя, задайте статический адрес `10.77.0.2/24` без шлюза. GX10 тоже сможет найти её по IPv6 link-local (`support-ctl net peers` покажет `fe80::…`), но регистрировать цель тогда нужно по этому адресу.
