# Playbook: ROS 2 robot — nodes, topics, nothing moves (робот ROS 2: ноды, топики, не едет)

Works over SSH on the robot computer (Jetson, NUC, Raspberry Pi). Source the environment first in every command:
`bash -lc 'source /opt/ros/$ROS_DISTRO/setup.bash; source ~/ws/install/setup.bash 2>/dev/null; <cmd>'`.

## Facts (READ)
- Distro and middleware: `printenv | grep -E "ROS_DISTRO|RMW_IMPLEMENTATION|ROS_DOMAIN_ID|ROS_LOCALHOST_ONLY"`.
- `ros2 doctor --report` (network, middleware, package versions).
- `ros2 node list`, `ros2 topic list -t`, `ros2 topic hz /topic` (5–10 s), `ros2 topic echo --once /topic`.
- Launch/service logs: `journalctl -u <robot-service> -n 200`, `~/.ros/log/latest/`.

## Typical causes
| Symptom | Check | Fix |
|---|---|---|
| Nodes on two machines do not see each other | same `ROS_DOMAIN_ID`, `ROS_LOCALHOST_ONLY=0`, multicast on the link, firewall | align env vars (CONFIG), allow UDP 7400–7600 |
| Topic exists but no data | `ros2 topic hz`; QoS mismatch (`ros2 topic info -v`) | match reliability/durability between publisher and subscriber |
| `/cmd_vel` published, robot does not move | motor driver node alive? e-stop? battery? driver topic/diagnostics | clear e-stop physically (operator), restart driver node |
| Sensor silent | device node exists (`/dev/ttyUSB*`, `/dev/video*`), udev rule, permissions (dialout, video) | fix udev/group (CONFIG); reconnect |
| Clock/TF errors | `ros2 run tf2_ros tf2_echo`, `use_sim_time` | fix time sync (chrony) or `use_sim_time:=false` |

## Safety
- Any command that moves the robot (publishing to `/cmd_vel`, actions, services that enable motors) is ACTUATION:
  the operator must confirm the robot is in a safe position, e-stop within reach, wheels free if possible.
  Use low velocities and short durations; send a zero command afterwards.
